# Code of Conduct

## Our standard

Airlock welcomes technical disagreement and rigorous security review. Contributors and maintainers are expected to communicate professionally, focus criticism on ideas/code/claims, and make the project safer and easier to use.

Examples of expected behaviour:

- give specific, actionable technical feedback;
- disagree with designs without attacking people;
- disclose conflicts of interest that materially affect a contribution;
- respect responsible vulnerability disclosure;
- avoid publishing another person's private information;
- help keep issues and pull requests relevant to the project.

Unacceptable behaviour includes harassment, threats, discriminatory abuse, deliberate disclosure of private information, sexualized conduct, sustained personal attacks, or intentionally sabotaging project collaboration.

## Enforcement

Maintainers may edit, hide, reject, or remove comments, commits, issues, pull requests, or other contributions that violate this standard. Repeated or severe violations may result in temporary or permanent exclusion from project spaces.

Security reports must follow `SECURITY.md`; this code of conduct must not be used to pressure a reporter into public disclosure.

## Scope

This policy applies in repository issues, pull requests, discussions, review threads, and other project-controlled spaces, and when someone is officially representing the project.

## Reporting conduct issues

For ordinary moderation issues, contact the repository owner through GitHub. Do not use public threads to disclose sensitive personal information.
