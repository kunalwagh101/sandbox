# Support

Airlock is an open-source project maintained through GitHub.

## Where to ask

- **Bug:** open a bug report using the GitHub issue template.
- **Feature or design request:** open a feature request.
- **Security vulnerability:** follow `SECURITY.md`; do not publish exploit details in a normal public issue.
- **Contribution question:** use the relevant pull request or issue and read `CONTRIBUTING.md` first.

## What to include for bugs

Please include:

- Windows edition, version, build, and architecture;
- Airlock commit SHA;
- exact command run;
- complete non-secret error output;
- whether the failure happened in preflight, initialization, launch, guest provisioning, or shutdown;
- whether Windows Sandbox works independently of Airlock;
- what you expected and what actually happened.

Remove usernames, local paths containing private information, credentials, tokens, private keys, customer data, and other secrets before posting logs publicly.

## Support scope

Maintainers can help diagnose Airlock behavior and documented supported-host contracts. There is no guaranteed response time or commercial support commitment. Unsupported Windows builds, modified security profiles, third-party installers, or manually weakened Sandbox settings may require reproduction on the documented configuration before they can be treated as Airlock defects.
